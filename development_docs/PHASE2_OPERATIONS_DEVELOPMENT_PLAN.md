## 1. 需求

### 1.1 本阶段交付范围

- 日志基础：平台日志库和独立上游调用日志库，独立连接、迁移、缓冲、配额、投递、补投和状态监测。
- 日志读取：有界历史筛选、稳定游标分页、脱敏详情、请求/任务关联、提交顺序及跨实例 SSE 续传。
- 更新运维：稳定更新事件、阶段操作树、源调用尝试、两份构建、转移/发布及十四源状态 API。
- 接口接入：九业务接口和十四源接口的版本化目录、参数/响应说明、合成示例及受控上游测试后端；业务测试复用现有代理。

- 运行管理：脱敏系统状态、容量/保留配置、受保护的清理预览与异步受理、操作审计。
- 工程交付：追加迁移、配置模板、Linux 部署与升级回退、单元和集成测试、实际验收证据、前端接入说明。

不新增业务查询接口、任意 SQL/URL 代理、通用账号角色平台、裸槽位切换或任意脚本执行。行政班独立查询尚无契约，不作为本分支必交接口。真实源联调和生产容量承诺仍归总计划第三步，本阶段以合成数据验证正确性及冻结预算。

首次初始化继续自动执行，不恢复手动 initialize 或 ctl。立即增量、强制全量、单表全量及失败重跑以当前管理路由为准，前置条件、互斥、冷却和幂等均由后端执行。所有 T/OI 使用仓库 Mock 或新增合成夹具，不读取真实人员样本、不调用真实上游、不向外部邮箱发信。

### 1.3 共用架构约束

| 范围 | 必须保持的规则 |

| 状态 | 转移、发布、检查、源成功进度、任务起止分开；未知返回 null/明确状态 |
| 操作 | 独立鉴权、后端前置检查；202 仅表示受理，断开客户端不取消已受理任务 |
| 通知 | 错误事实与发信分离，保存不发信；关闭取消未开始/待重试，通道接受不等于收件箱送达 |
| 清理 | 保护恢复/读者/补投/通知引用，不接受客户端路径、SQL 或任意模式 |
| 兼容 | 只追加迁移，旧数据可追溯；代码回退不自动还原数据或撤销已发生动作 |
| 前端 | 新 UI 留到整体重构；本分支通过 HTTP/SSE 客户端验收后端 |

## 2. 方案

### 2.1 开发与核对方式

P27—P35 保留阶段目标、依赖和产物；第 2.2 节的 `Pxx.yy` 是实际工作单元，包含正常/失败路径、测试代码、必要配置/迁移和文档。不按文件数量拆任务，不把测试集中留到最后。

1. P 子框只在实现、对应测试代码和 review 完成后勾选，不要求当前已暂停的测试运行。部分完成的步骤保留 P 子框未勾选，在其下分别勾选已完成实现/材料并列出剩余测试源码或实现；不能用部分完成替代整个步骤。T 子框必须有运行通过证据，草稿、静态检查和构建成功均不能代替单测。
2. 按阶段和有效子编号持续推进；未来模块以明确接口和 Mock 隔离。本地继续开发不代表依赖已验证，阶段正式验收须同时满足 P/T，风险单独记载。
3. 每步聚焦一个可描述、可回退的改动，提交使用 `feat:`、`fix:` 等项目约定前缀；提交/推送依当前授权执行。Phase 1 的历史推送/合并安排不自动成为本分支的新操作授权。
4. 自动单元、race、集成和容量测试只在 GitHub Actions Linux runner 运行，本地只编辑和静态检查。沿用锁定的 Go、镜像与 Bash/路径/权限规范。
5. review 后先修复再复核，覆盖对应 T 和受影响已有回归；未运行、跳过、超时和未发现测试不算通过，不借用旧接口阶段的 CI 豁免作为证据。
6. 迁移仅追加版本，逐步说明升级/回退；代码、数据、缓冲重放、已发邮件及已发生发布分别说明，代码回退不撤销外部事实。
7. 全部有效后端 P/T 完成后才运行新增 OI01—OI07；已有 CI 回归保留。OI 失败先修复并回归相关 T，再重跑受影响 OI。

开发记录用 `verification/Pxx.md`，逐步记录文件、决策、review、SHA（如已提交）、验证和回退边界；测试记录用 `Txx.md`，关联实际测试名、Mock、命令/退出码、通过/失败/跳过数量和 Actions 工件。OI 同样保留实际证据。阶段末只汇总，不集中补此前遗漏的测试。

当前 `DEVELOPMENT_PLAN.md` 被既有 `.gitignore` 忽略，其本地入口可同步；本阶段可跟踪计划须自包含需求、方案和测试，不能依赖忽略文件才能理解交付。

### 2.3 公共协议与实现安排

**身份及入口。** 浏览器继续使用同源 worker 会话及现有写请求 CSRF 校验；查询服务读日志库，worker 使用专用固定目标代理及独立内部管理凭据。业务 `X-API-Key` 不能作为管理认证，业务代理不扩展成任意管理转发。日志读取、源测试、通知配置/测试及清理分别授权，旧 token 不自动增权；单管理员会话按明确能力配置，不新建角色平台。代理丢弃客户端提供的内部身份/权限头，再传递服务端确定的主体及权限范围；内部服务同时验证专用凭据和范围。列表、详情、订阅和重连均鉴权，已建立流最迟每 15 秒复核会话/权限，失效即停止转发。现有 worker 会话保存在进程内，重启后重新登录；跨查询实例续传不等于跨 worker 保留登录。

**单管理员配置（2026-10-13 按用户确认调整）。** 同一个管理员登录后拥有全部已实现管理动作权限，日志路由默认启用；标准部署不再填写三项日志密钥/令牌和四个读取/维护 URL。日志读取及受限清理自动使用对应服务凭据，迁移自动授予角色；SNAPSHOT_KEY 通过独立用途标签派生游标密钥与内部服务令牌，query 不接收管理员密码。会话/CSRF/数据保护与依赖就绪校验保留。

**双库与缓冲（2026-10-13 按用户确认调整）。** 一个独立于 M/S 的 db-log PostgreSQL 服务及 pg-log 卷承载 logs / upstream_logs，不再要求两套日志服务。DATABASE_UPSTREAM_LOG_URL 使用独立凭据及逻辑库，两库保留各自迁移及权限。部署校验实际 cluster/OID/库名，同实例不同库允许，实际同库拒绝。实例故障与资源额度共享；单库权限/表结构故障仍逐源处理，数据库暂不可达时对应身份校验保持未通过，恢复后检查通过才启用读写。双库模式缺配置或 schema 不兼容时拒绝相应能力就绪，兼容模式须显式可见。已正确配置但暂不可达的单日志库进入降级/补投，启动及运行期间均不阻断另一日志库和业务；须拆开当前全连接 Ping 失败即退出的装配，并避免 Compose 将日志健康设为业务启动硬依赖。平台接收 request/task/step 和新增 audit，上游接收 call/attempt；P27 定义 audit 及测试关联字段，P28 同步事件校验、脱敏、schema 与分流。两源独立目录、配额、Dispatcher 和计数，目标库确认后回收缓冲；满额拒绝该源新增记录并计数，不静默丢弃旧文件或阻塞另一源。旧平台 call/attempt 原地保留；切换时停止旧事件生产，旧缓冲按原目标补投完毕，再停止旧 Dispatcher 并排空写事务，确认清单与切换边界后才启用新分流。旧目标未恢复或补投未确认时不得把升级标为完成。

**历史与游标。** source 固定 platform/upstream；筛选含 mode、时间、kind、phase、outcome、operation、task_id、request_id，可按 test_run_id 关联源测试。时间为带时区 RFC3339、UTC 微秒精度，2000—9999 年，拒绝更细精度；page_size 默认 50、最大 200。`mode=history` 为默认，发生时间范围 `[from,to)`，缺省 to 为首请求服务端时间、from 为 to 前 24 小时，最大跨度 7 天；返回 `stream_cursor=null`。`mode=live` 用于历史与实时衔接：to 必须省略并返回 null，from 缺省为首请求时间前 24 小时，要求首请求时间减 from 在 0—7 天内；后续只匹配 `occurred_at >= from`，from 固定不滚动。首次 H 限制初始历史，后续新发生事件不会被旧 to 排除；早于 from 的晚到事件按筛选排除，无遗漏保证仅针对匹配记录。拒绝未知/重复/空参数及非规范页大小。标识输入显式使用 `id_format=raw|correlation`，默认 raw，仅接受服务生成的不透明 ID；raw 在可信入口按既有算法摘要一次，correlation 按已脱敏格式校验并原样使用，禁止靠长度猜测。游标仅携带规范化摘要，不携带原始载荷。

历史按提交序号倒序，首次固定已提交高水位 H，分页只读 `sequence <= H`。每页及每个实时批次在同一短只读可重复读事务中读取数据库代次 epoch、清理水位和记录，避免校验水位后被并发删除而静默漏项；不得跨 HTTP 响应或连接持有事务，依据 [PostgreSQL 事务隔离说明](https://www.postgresql.org/docs/current/transaction-iso.html)。签名游标绑定版本、源/epoch、规范化筛选、权限范围、方向、H/位置、签发时清理水位和有效期；密钥多实例共享且不复用业务 key，按 key_id 轮换，旧 key 至少保留到其游标过期，紧急撤销后要求重查。默认有效 24 小时，翻页/重连不续期；省略参数继承原筛选，不按当前时间重算窗口。序号和水位在 JSON 中使用十进制字符串。篡改/跨源/换条件 400，权限不匹配 403；合法过期、epoch 变化或受清理影响为 409 `cursor_expired`。floor 表示已删除连续前缀的最大序号；历史 floor 高于签发值即保守重查，实时仅最后扫描位置小于 floor 时失效。数据库恢复或重建须轮换 epoch 后再开放读取，不能以旧签名续接重置后的序号。

**提交顺序。** 每库以事务计数行串行分配新事件序号，计数和事件同事务提交，锁保留到提交/回滚；重放不新增事件，同键不同内容拒绝，重复比较排除 received_at 等存储生成字段。仅已提交计数作为 H，空库为 0，不以数据库 sequence/BIGSERIAL 的最大值代替。旧记录按 received_at、event_id 的确定顺序回填，不声称恢复其历史真实提交顺序。升级先停止旧事件生产、按原目标补投完旧缓冲，再停止旧 Dispatcher 并确认事务排空；迁移同时建立非空唯一序号及写入协议约束，通过受限写入口分配序号，收回可绕过协议的直接写权限，未升级 writer 明确失败。迁移、投递、查询、维护分别授予所需权限，查询账号不可写，投递账号不可任意删除。可靠 SSE 仅在 schema/权限及全部 writer 能力检查通过后开放；旧 writer 不满足新写入约束，不支持直接降级镜像恢复写入；代码回退须保留兼容的新投递组件，无法分离时进入停写维护状态。恢复旧备份属于独立数据恢复流程，须声明恢复点、潜在数据损失并轮换 epoch，不通过放松约束恢复旧写法。

**实时续传。** 仅 live 首次历史产生 stream_cursor，其位置为 H，从 H 后正序补查已提交记录；续页返回同一初始订阅边界，不把最后一条倒序历史的位置当成实时起点。客户端可一边加载 H 内旧页一边订阅 H 后新事件，按 source/epoch/event_id 去重。event 帧的 id 为已发送事件对应游标；checkpoint 帧只推进到完成扫描且前序匹配事件已顺序写出的连续位置；心跳不改变 id，依据 [SSE 帧及 Last-Event-ID 规范](https://html.spec.whatwg.org/multipage/server-sent-events.html)。首次使用 cursor 参数，重连优先使用非空 Last-Event-ID；仍须校验 URL 中源/筛选，损坏的头不得回退到旧 cursor。数据库与网络不保证恰好一次，断线允许重放但不能跳过未发送匹配项。建连前校验签名/权限并用 HTTP 返回错误；建连后故障发送不推进位置的 control 帧并关闭，帧含稳定 code/retryable/rebuild_required，写不出控制帧时直接断开。签名到期须重建历史，5 分钟连接到期可携末次游标续连。跨查询实例依赖持久序号/epoch 和共享签名配置，不依赖进程队列。

**资源初始预算。** 日志查询 5 秒、响应 2 MiB、每实例 8 个并发读取；SSE 每连接缓冲 200 条/2 MiB、心跳及权限复核 15 秒、写超时 5 秒、最长连接 5 分钟、每实例 16 个连接。单条输出最多 256 KiB，载荷白名单及截断在入缓冲前完成并标记；旧超大/损坏记录返回明确错误，不先无限读取再检查。每批扫描最多 200 条/2 MiB，以最后扫描序号推进，空批等待 1 秒；每源最多 2 个读取任务、全实例共用有界调度，不按每个订阅无限创建轮询器。不同筛选/权限独立判断，共享只复用读取，不能跨权限广播。共享读取计入 8 个读取预算，稀疏筛选也分批释放资源，不无界追到当前头部。配置须校验；建连/请求前超限 429/Retry-After，已建连按 control 帧关闭；慢客户端可续传，入库不等客户端，代理关闭缓冲并配置流式写超时。以上为拟定保护预算，容量承诺必须由 OI07 的冻结规模验证。

**事件与测试。** 更新事件以 task_id 映射，恢复沿用原事件，主动重跑新建并保留 predecessor_id；日志缺失不改变控制任务事实，日志诊断失败单独标明 unavailable。源测试仅接受十四源目录 ID/契约版本及参数白名单，固定目标/环境/凭据，只请求一页、不自动翻页；和同步采集共用源限流/冷却预算，测试低优先级，忙碌时拒绝或有限排队，不绕过冷却。每实例最多 1 个执行、控制区队列最多 20 个待执行，总期限自受理起 30 秒（含排队/请求/收尾）、响应最多 2 MiB，禁重定向，禁任意 Header/URL/环境覆盖；新增 purpose/test_run_id 表达测试身份，不伪造同步 task_id 或成功进度。控制区新增独立管理作业记录及租约/所有权，不套用同步任务的模式枚举：queued → running → succeeded/failed/interrupted，未执行即超时的 queued 直接 failed；重启仅恢复原期限内的 queued，失去执行者的 running 记 interrupted，不自动重发上游请求，旧执行者迟到不能写回。HTTP/业务目标结果与作业执行结果分开。完整结果仅在执行实例内存保存最多 10 分钟、总计最多 20 MiB，限提交主体及对应权限读取；到期/淘汰/重启返回 result_unavailable 及实际状态/脱敏摘要，不冒充空成功。长期审计只留摘要，结果不入日志/缓冲/持久任务，读取任意实例不保证内存载荷仍可用。九业务测试继续同步复用已有代理，不进入这套源测试队列，保持快照及单一执行链路。

**通知与清理。** 通知设置在控制区按 revision 乐观锁更新，开关、收件人和规则原子提交；首次默认关闭，空收件人强制关闭，未配置或配置无效的 SMTP 拒绝启用但不阻断主链路，临时不可达只影响投递/通道状态。旧有效 MAIL 配置经升级检查一次性导入已存在收件人和原启用状态；不完整配置保持关闭并报通道不可用，重入不覆盖数据库设置，不静默添加地址。错误事实及规则去重写在控制区，不依赖日志库；控制区不可用时无法保证新增通知，须如实报告，不能宣称进程停机时自身仍能发信。收件人最多 20 个，每地址最多 254 字节，只接受裸邮箱地址并拒绝 CR/LF；去首尾空白、域名小写、本地部分保留大小写后去重。规则只引用服务端稳定错误码白名单，不执行客户端表达式；去重键为错误事实 ID/规则 ID/规范化收件人，重放不重新扩散投递。每条投递固定规则版本/收件人，新增收件人不补发旧错误，移除地址/禁用规则取消对应 queued 与待重试。关闭与领取发送在同一配置锁下排序：关闭先提交则不得领取；已持久进入 sending 的尝试可能已经交给通道，标明进行中/结果未知，不能保证撤回。SMTP 接受记 accepted 而非 delivered；确定的临时失败按有限预算退避，明确永久拒绝不重试；发送后应答不明记 unknown，默认不自动重试，显式新测试是新任务且说明可能重复。新投递每人最多 3 次总尝试（含首次）、从入队起总期限 24 小时；确定临时失败后依次等待 1 分钟、5 分钟，等待也计入期限。旧投递迁移保留已用次数/结果，预算已耗尽不重置；旧 sending/应答不明按 unknown 处理，重新启用不复活 cancelled/unknown。保存不发送，显式测试仅用匹配 revision 的已保存授权地址；无通道或关闭时拒绝。

清理只接受对象白名单；预览无删除副作用，返回主体/范围/策略 revision/对象版本绑定的 10 分钟预览 ID，过期或改变范围须重做。执行不能只做一次引用检查：复用现有 retirement/读者租约/恢复保护协议，在同一协调锁下核验并标记退休，所有引用登记入口也须遵循该协议，阻止新引用后再删除；活跃槽位、未确认缓冲及未终结通知/管理作业依赖不可删除。日志按入库 received_at 而非 occurred_at 判保留期，只删除无保护引用的连续序号前缀；批次删除和 floor 推进同一事务，遇到受保护记录停止，不跨越空洞。本阶段不清理补投去重标记，保留 event_id/规范化内容摘要/原序号；即使事件载荷已清理，重放仍按已接收确认而不重新插入，同 ID 异内容仍拒绝，标记容量计入监测。两库分别提交并报告，不声称跨库原子清理。清理任务及受理审计先持久化，执行按对象记录确认/失败/跳过，持租约按批次恢复；日志审计不可用时由控制区 outbox 补投。执行后返回实际数量及 partial_failed，不将预览数量冒充删除数；客户端断开不撤销删除。
