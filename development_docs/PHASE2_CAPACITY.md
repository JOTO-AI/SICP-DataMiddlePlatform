# 第二阶段容量约束与测量入口

冻结日期：2026-10-12。以下是代码约束与验收门槛，**不是已测得的生产能力**。本次用户暂时豁免 CI 等待，本地不运行测试。

| 请求族 | 默认页大小 | 每次源读取预算 | 成功门槛 |
| --- | --- | --- | --- |
| 组织、学生、教职工 | 1000 | 100000 行、1000 批、每批 500、20 秒、64 MiB 累计计费 | 完整校验后返回正确 total 与一页；不截断成功 |
| 教师教学班、班级成员 | 100 | 同上，关联及重复读取共用预算 | 全候选与跨学期校验完成；接口 8/9 去重人数一致 |

所有分页最大 1000、响应最大 16 MiB。64 MiB 包括源字段及显式计费的关联集合，不是 Go 堆或 RSS 上限；实际容器内存还包括 map、对象、连接、缓存和并发。默认每进程最多 8 个执行、64 个等待、整体执行 30 秒（包含等待）；即使仅按请求账面额度也应预留 8 × 64 MiB，再计运行时及其他资源。不得套用后台构建限额扩大前台请求。

学生查询完整读取 basic/enrollment 并验证集合相等；联系人不参与筛选，仅取本页。35,000 人、每页 1000、无额外关联时为 71,000 源行与 145 次批读取；真实列宽、辅导员、组织等会增加计费。单元容量夹具包含全部源列的 null，不能以省略字段的小对象代替实际行宽。

教师查询先以学期、教师编号字面子串选候选，再以完整教师 token 确认。之后按班级读取所有学期和教师的课次，保留共同授课教师并拒绝跨学期歧义。SQL 子串筛选减少传回应用的行数，不保证数据库无全扫描，必须结合 EXPLAIN 测量。名单根据关系去重，不使用 XDRS 或行政班推导。超大候选/名单超限返回 422，只代表保护生效，不代表全量同步验收通过。

连接默认每个业务池 16、控制池 16、日志池 16。多副本按 `QUERY_REPLICAS * (2 * QUERY_DB_BUSINESS_MAX_CONNS + QUERY_DB_CONTROL_MAX_CONNS)` 计算单业务实例最坏连接需求，并加 worker、迁移和运维预留；不能把每池上限当作整个部署上限。配置入口见 `.env.example` 与 `deploy/README.md`。

`TestI11_Phase2FullScaleSourceQueries` 使用真实 PostgreSQL、完整迁移和确定性 sequential-v1 合成源：35000 学生、2600 教职工、540000 课次、490000 关系；热点教师 6000 课次、单班 5000 人。逐页验证学生、教职工和名单，精确学生查询及热点教师人数；记录每次服务耗时、SQL 次数、源行、累计分配增量与两个班级游标查询的 EXPLAIN。输出 `artifacts/integration/I11-capacity.json`，绑定 GITHUB_SHA、seed、规模和预算；失败报告不能当成功证据。

该入口是服务/数据库测量，尚不证明冷热 HTTP 缓存、峰值 RSS、生产并发、同镜像重启或兼容回退。I11 总验收仍需这些运行证据以及更宽字段/更多关联的分布；本次未执行，计划 I11 保持未勾选。I07—I10 覆盖 HTTP 与发布路径，原四接口构建基线保持独立。
