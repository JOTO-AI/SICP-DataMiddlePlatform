# B06 有序基线与增量合并

实现和静态 code review 完成，GitHub 验证待确认。

生产目标准备为普通增量启用 OrderedBaseline：旧目标文件按键顺序逐行消费，仅新采集输入进入外部排序。双路合并沿用原 less 比较器，包含历史时间和原值排序，再交给原 keyGroup 处理整行替换、迟到记录、等时间冲突及增量保留规则。全量／强制全量仍走原完整排序与删除语义。

旧基线逐行检查字段、严格递增主键与单行大小；最终仍核对完整旧摘要。新增头部状态只保留一个基线行和一个增量行，不将完整旧数据写入排序文件。异常和取消继续调用 Abort、关闭排序读者、清理本次私有临时目录；候选组退出仍等待所有表任务结束。

BT06 增加固定随机种子的多轮差分，比较旧全排序路径与新路径的全部目标行、摘要、变更数及临时写入量；覆盖基线乱序／重复／错误摘要、迟到旧版本和等时间冲突。原缺字段替换、全量删除、增量未返回保留以及故障不完成测试继续执行。

本地仅 gofmt 和差异复核，未运行基准。1%／100% 变化的实际临时写入和耗时仍由 GitHub 容量工件报告；不把减少排序写入等同于已经满足 30 分钟目标。
