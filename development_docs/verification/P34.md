### P34.03 引用退休和扩展日志对象开发收尾

新增不可变迁移 control_011 / logs_009 / upstream_logs_008，不改历史 checksum。清理目录明确为 request/task/step/call/attempt/audit；M/S 业务数据、封存文件、日志缓冲和 receipts 不属于此 API 的删除目标，既有业务资源 retirement 协议继续保护它们，并作为任务日志退休的前置引用检查。

预览从最多 1000 行日志前缀读取服务端身份，控制区检查任务/作业终态、执行所有权、槽位、读者 SQL/租约、分页快照、资源/恢复/补投引用、发布 outbox、未处理错误事实和未终结逐人投递，已确认审计可清理；缺失/未知身份保守保护。仅保存实际 eligible 前缀的引用，预览不退休。执行在控制区共享登记屏障的排他侧重查并提交永久退休栅栏，再把确认写入目标日志库，最后同事务删除连续 received_at 前缀并推进 floor/回执。所有关联表 INSERT/UPDATE/DELETE 登记入口有数据库触发屏障；退休版本行的 FOR SHARE 使旧 repeatable-read 事务不能绕过退休。

跨库故障可能留下尚未删除的退休栅栏，不能撤销栅栏后复活旧依赖；历史控制记录仍可读，新的主动重跑使用新 task_id。删除回执始终先于策略检查，恢复不重复计数；晚补投依 received_at 重新保留，原 ID 重放由永久 receipts 确认且不复活已删载荷。并不声称跨库原子提交。代码回退必须保留新增触发器/退休标记；回退数据只能恢复协调备份，不能手工清空栅栏。

cleanup_retirement_test.go 覆盖全部保护类别、通知占用前缀、预览无退休、主体/期限、幂等受理、执行前新增引用、旧事务等待与旧快照拒绝、received_at 晚到及已删重放。retirement_test.go 补固定身份/上限；修正旧 migration 测试的硬编码目录数量与末尾迁移假设。Linux integration/operations/migrate 源码编译、go vet 和人工 review 完成；未运行任何测试或迁移。P34.03 已勾选，下一项 P34.04。
