## 人工 code review

逐项检查 Registry、凭据混用、物理身份、迁移顺序/重入/错误、现有调用点和阶段边界：

1. 仅比较 URL 不足以隔离实例：读取实际 system_identifier，日志库之间和与业务/控制实例均不可相同；不同数据库名也不放宽。
2. 配置 dual 而旧装配只打开六个池会静默混投：在 Runtime、adapter、迁移入口明确拒绝，等待 P28.03。
3. 预检和写入间可能换后端：在执行迁移的事务中再次匹配完整身份，写入前拒绝变化。
4. 新模式要求会影响原单测及集成环境：扫描全部已跟踪 LoadRegistry 调用点，补环境变量；数据夹具和查询预期保持原样。
5. 双库迁移不应写入其他 Domain 的 ledger：加锁后检查 domain，错误拒绝并回滚；新增测试使用每连接独立 ledger。
6. 迁移错误此前包装底层错误可能带出凭据：改为阶段错误，不输出驱动内容。身份读取、事务清理失败不产生有效证明。
7. 全目标预检只用于部署，不可用于运行期全局健康判定；独立降级、重连验证和资源释放仍在 P28.03 处理。
