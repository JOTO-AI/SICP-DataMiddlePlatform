## 实现与技术决策

| 项目 | 决策 |
| --- | --- |
| Go / HTTP | 固定 Go 1.26.8，标准库 net/http ServeMux；go.mod、Linux CI、Docker 构建一致。无第三方运行依赖。 |
| Linux / CPU | GitHub Actions ubuntu-24.04；部署 linux/amd64。按用户后续指示，正式单测验收仅在 GitHub Actions 执行，不再运行本地单测。 |
| 构建 / 运行镜像 | golang:1.26.8-bookworm → debian:bookworm-slim；CGO_ENABLED=0，非 root UID 65532，系统 CA，Go 内嵌时区。正式运行无 libc 动态链接要求；race 检测需要 GCC/libc 开发包。 |
| 数据库（P02 接入） | M/S 和独立日志实例统一 PostgreSQL 18.6；访问库选择 pgx/v5 v5.11.0（原生批量 COPY 与连接池）。P02 接入时固定到 go.mod/go.sum，P01 不引入未使用的驱动。 |
| 固定控制区（P02 接入） | db-m 内独立 sicp_control 数据库，使用独立连接和账号；不在 M/S 的业务槽位数据库内，不随槽位覆盖。控制库不可用时不发布/转移；不把 Redis 和多库当作普通原子事务。 |
| 配置 | 环境变量注入，查询服务必填 QUERY_API_KEY；HTTP_ADDRESS 默认回环地址，worker 不要求查询凭据。基础设施与邮件配置由对应任务引入，不伪造连接成功。 |
| 超时 | 默认启动 15s、退出总预算 10s、HTTP 读取/头部 10s、写入 30s、空闲 60s；显式值必须在 (0,24h]。 |
| 生命周期 | 工厂按序初始化，失败逆序释放；返回部分资源也释放。关闭按一个总预算执行，超时资源及未启动清理资源记 incomplete，错误记 failed；不声称 SQL 已排空。 |
| 接口 | 四个 POST 路由使用独立 operation ID；完整 DTO 逐字段对齐业务设计。空响应数组为 []、可空值为指针，无 omitempty。 |
| 就绪 | /livez 区分 /readyz。查询占位处理器和未实现同步器均未就绪；依赖就绪不能使占位业务变成就绪。 |
| 可注入边界 | 时钟、随机源、HTTP 客户端、文件存储、缓存、通知、资源关闭、就绪检查、依赖工厂与监听器；P02 定义数据库事务/行仓储，不提前虚构业务实体。 |
| 安全边界 | P01 没有开放业务数据；鉴权和严格参数解析在 P06。配置错误不回显输入，启动错误不回显底层凭据，Docker 构建上下文只含代码。 |

版本参考：[Go 下载](https://go.dev/dl/)、[PostgreSQL 支持版本](https://www.postgresql.org/support/versioning/)、[pgx 官方项目](https://github.com/jackc/pgx)。固定版本升级需要统一修改并重新验证，不在启动时自动切换。

## 代码复核

复核方式：实现完成后逐文件检查控制流、契约表、错误分支、资源所有权、并发访问、CI 和容器配置，并将发现的问题修复后回归。未使用并行代理。

已发现并修复：

1. 调用方清空待定规则副本可能绕过启用检查：改为同时检查权威目录；新增回归断言。
2. 仅依赖就绪可能误报业务就绪：增加真实处理器启用状态，Mock 路由注册不标记就绪；新增回归断言。
3. 超时关闭可能仍返回成功退出：记录 incomplete，Run 返回非成功；关闭错误不阻止预算内其余资源释放。
4. 异常路径输入可能触发 ServeMux 的模式解释：拒绝占位符、非规范路径、转义与控制字符入口。
5. 首轮信号单测暴露 Serve 尚未登记 listener 时 Shutdown 提前返回的竞态：HTTP 资源显式持有 listener，关闭返回前兜底释放，确保依赖释放前停止接收；重复执行信号测试验证。

最终测试及复核状态见 [T01](T01.md)。未来未定业务语义已记入[待定规则](../P01_PENDING_RULES.md)，不计作 P01 缺陷或业务已交付。
