## P05.01：统一事件身份与时间模型

- 新增 events 的统一 Recorder/Span，服务生成随机身份；request/task/step/call/attempt 分层关联，M/S 步骤分别生成 step_id。每个事件拥有稳定事件键，开始、业务完成、传输完成分别记录。
- UTC 发生时间来自注入 Clock，耗时取时间差（生产 SystemClock 保留单调时钟）；只有开始时不构造结束时间/状态。源 fetchPage 实际重试接入同一 call、不同 attempt 的记录，查询可使用同一 Request Span，业务成功后传输断开分别记录。
- 日志开始记录失败拒绝新调用；已经发生的业务结果保留，结束记录失败单列 ObservationError 并经 Collect 向上传递。无任意请求/响应文本进入事件；P05.02 增加统一脱敏和载荷上限，P06 接查询执行器。

## P05.02：缓冲前脱敏与载荷上限

- 新增 Sanitizer → 私有 SafeEvent → SafeSink 边界；零值安全载荷无效、导出的 Bytes 为副本。Guard 在 sink 接收前验证并净化，仓储不能用公开字段构造安全载荷。
- 采用保守自由文本策略：自由文本、自由字段名和值均不复制，只保留总字节数、字段数、脱敏/截断标记。另设类型化白名单 Metadata，保留目录验证的源类别/固定路径、模式、页码/页大小、有效窗口、固定查询 Operation 和失败分类；FetchPage 已实际附上源页与失败类别，合法诊断不丢失。
- 身份采用 HMAC-SHA256 稳定映射，覆盖 event/entity/request/task/step/call/attempt；即使原 ID 是人员标识也不会原样写入日志。`Sanitizer.Correlation(controlTaskID)` 是控制任务查日志的统一转换方法；同一部署的 query/worker/日志查询必须共用持久 32 字节密钥，禁止每次启动随机生成；P15 必须校验缺失/零密钥并拒绝启动。本步构造器已强制有效密钥，未改共享 config。
- 恢复已安全载荷不做二次映射，但严格验证所有身份为 64 位小写十六进制摘要；自由文本不能通过持久文件注入原始 ID。配置秘密还对最终结构化载荷做排除；所有原始事件/详情/配置对象均有安全 formatter。
- 单事件上限显式配置 512B—1MiB，详情预算独立；元数据超过总上限拒绝，不截断关联身份。无大响应复制，仅对传入详情计数。sink 返回错误替换为固定安全分类；Guard 防止同上下文递归记录缓冲自身操作。
- review：独立复核补齐 HMAC 身份映射、目录白名单诊断、恢复摘要校验、超长小数窗口拒绝与配置对象解引用 formatter 防护；最终复查通过。仅 gofmt/diff；等待 GitHub CI。实际文件、数据库和邮件适配在后续小步接入相同安全载荷。
