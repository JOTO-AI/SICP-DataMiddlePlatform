# P02 开发与代码复核记录

## P02.01：四槽位与固定连接注册

- 实现：`internal/storage/registry.go` 及邻接测试；`configs/database.env.example`。
- 决策：以 M/0、M/1、S/0、S/1 显式选择不可变连接描述；不存在默认业务位置。固定控制库位于 M 的独立数据库，日志使用第三个独立端点。槽位内两数据库必须不同，连接身份比较不受账号、主机大小写和端口前导零影响。
- 配置：六个 URL 全部显式提供用户名、主机、端口、数据库和 sslmode；拒绝主机/数据库覆盖参数、多主机、重复参数与缺项。部署需保证不同主机名没有指向同一实例的 DNS 别名；运行时连接池、真实权限及数据库检查分别在后续适配器和 I01 实现。
- 接入边界：本步提供纯配置注册，不创建网络连接，不改变 P01 尚未装配的服务就绪状态；P15 使用此入口装配数据库适配器。
- 复核：逐行检查位置拒绝、数据库隔离、输入副本、URL 解析和错误/格式化脱敏；修正字符串转义检查，补充零值注册表、账号不同但目标相同、端口规范化、非法位置及固定连接回归。复核通过，无未解决问题。
- 本地检查：仅格式和 diff 静态检查；不在本地执行单测。T02-01/T02-02 及已有回归在 GitHub Linux CI 执行，结果记录见 T02。
- 提交/push：当前 `main`，本小步提交信息 `feat: register isolated business and fixed database connections`；SHA 与 CI 链接在后续必要记录更新时补录。
- 回退：同时回退注册模块、测试、模板和本步文档即可；本步没有应用数据库迁移或写入运行状态。
