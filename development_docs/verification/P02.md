## P02.03：源字段无损绑定

- 实现：`internal/storage/value`；TEXT/JSON/timestamp 参数编码、按数据库类型还原和错误边界测试。
- 规则：TEXT 缺键/null 都绑定 SQL NULL，空字符串/字面 null/前导零/空格原样保存；JSON 缺键绑定 SQL NULL、显式 null 绑定 JSON 文本 null。JSON 原始 token 不经 float 或数值规范化，读时使用列 `::text`。
- 时间：仅接受无时区的四位年日期及秒，允许空格或 T 分隔、最多六位小数；拒绝非法日期、闰秒、时区后缀、年零和超精度，绑定 time.Time 的日历字段，不转换时区。读取输出规范化字符串，保留值而非输入排版。
- 还原边界：SQL NULL 返回 nil token，JSON null 返回非 nil 的 null token；TEXT/时间列不能恢复缺键与显式 null 的区别，该证据仍由 P03/P04 的源暂存维护，不伪称数据库完整恢复源对象。
- 代码复核：确认所有 JSON 数字仅以原文传递、参数无整数编号化；检查时间精度/日历和错误脱敏。额外发现 Go JSON 字符串解码会替换孤立 UTF-16 代理项，增加显式拒绝检查及合法代理对/字面转义回归，避免静默损坏文本；TEXT NUL 和非法 UTF-8 明确拒绝。复核通过。
- 验证：本地仅 gofmt/diff 静态检查；对应 T02-03/04/05 和前序回归等待 GitHub Linux CI。
- 提交/push：`main`，`feat: bind source values without losing tokens or time precision`。
- 回退：删除本步包、测试并回退记录；未接入运行服务、未写数据库，无数据恢复操作。

## P02.04：受限目标的批量仓储

- 实现：`internal/storage/source` 的十四表列白名单、流式重建、按主键分批读取；扩展独立 QueryExecutor/Rows 适配边界。
- 写入：所有目标先通过位置、代次、候选和锁内状态检查；只允许无读者、关闭准入、所有权有效且不承担查询的实例。首次初始化需要显式状态，活动位置未知时拒绝。业务写入口无法选择控制/日志连接，SQL 标识仅来自固定列目录。
- 批次：默认由调用方指定，每批最多 1000 行/8 MiB 原值；首次批次内 TRUNCATE，全部列参数化 INSERT、缺列 SQL NULL，不用 upsert 消解重复主键。每批独立提交；后批失败返回已完成批次/行数并保持 Complete=false，仓储不宣布候选 ready。
- 读取：固定调用位置、主键 C 排序、绑定游标与 LIMIT；JSON 列按 ::text 读取，沿用 P02.03 还原，后续行/游标错误或预算超限拒绝整个读取结果。运行时读取资格和组合句柄由 P06/P11 装配，当前未对外启用查询。

- 代码复核：修复活动位置缺失与初始化混淆，添加初始化明确放行/位置未知拒绝；检查取消、释放失败、批次失败及整行 NULL 参数，列目录对照独立字段清单。复核通过，本地只做格式和 diff 检查。
