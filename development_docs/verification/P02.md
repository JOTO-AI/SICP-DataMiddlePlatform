# P02 开发与代码复核记录

## P02.01：四槽位与固定连接注册

- 实现：`internal/storage/registry.go` 及邻接测试；`configs/database.env.example`。
- 决策：以 M/0、M/1、S/0、S/1 显式选择不可变连接描述；不存在默认业务位置。固定控制库位于 M 的独立数据库，日志使用第三个独立端点。槽位内两数据库必须不同，连接身份比较不受账号、主机大小写和端口前导零影响。
- 配置：六个 URL 全部显式提供用户名、主机、端口、数据库和 sslmode；拒绝主机/数据库覆盖参数、多主机、重复参数与缺项。部署需保证不同主机名没有指向同一实例的 DNS 别名；运行时连接池、真实权限及数据库检查分别在后续适配器和 I01 实现。
- 接入边界：本步提供纯配置注册，不创建网络连接，不改变 P01 尚未装配的服务就绪状态；P15 使用此入口装配数据库适配器。
- 复核：逐行检查位置拒绝、数据库隔离、输入副本、URL 解析和错误/格式化脱敏；修正字符串转义检查，补充零值注册表、账号不同但目标相同、端口规范化、非法位置及固定连接回归。复核通过，无未解决问题。
- 本地检查：仅格式和 diff 静态检查；不在本地执行单测。T02-01/T02-02 及已有回归在 GitHub Linux CI 执行，结果记录见 T02。
- 提交/push：当前 `main`，本小步提交信息 `feat: register isolated business and fixed database connections`；SHA 与 CI 链接在后续必要记录更新时补录。
- 回退：同时回退注册模块、测试、模板和本步文档即可；本步没有应用数据库迁移或写入运行状态。

## P02.02：迁移与权限定义

- 实现：`internal/storage/database.go` 的数据库事务边界、`internal/storage/migrate` 的嵌入迁移及测试、`migrations/roles.sql` 和运行说明。
- 源表：四槽位各自执行同一业务迁移；十四表 274 列逐字段落库，256 TEXT/15 JSON/3 TIMESTAMP WITHOUT TIME ZONE；全部主键为 TEXT、主键索引由 PostgreSQL 建立；普通列可空，无源表外键、派生字段或额外源业务表。
- 控制与日志：固定控制库分别保存任务、步骤、检查点、调度、执行互斥、组合、槽位、候选、进度、两类 outbox 与读者；日志库采用事件 ID 去重的独立事件表。源时间与业务动作时间分开，未知动作时间可空。
- 迁移：每库事务级 advisory lock，DDL 与版本/SHA-256 校验和原子提交；重复跳过，冲突/执行失败/记账失败/提交失败不报告成功；取消后的回滚有独立五秒预算。
- 权限：管理员运行角色创建和迁移；query 仅有源表 SELECT，worker 有业务写权限，logger 仅访问日志事件；query 在控制区仅获得读取状态和读者登记必需权限。部署登录账号、PUBLIC 权限撤销与组成员配置见 migrations/README.md，真实效果留 I01 验证。
- 独立预期：DDL 基于仓库 Mock 元数据目录生成；测试 expected_columns.txt 独立从已确认字段规划提取，覆盖字段名、类型和主键，不调用生成器作为预期。
- 代码复核：检查源列目录、NULL/JSON 类型、域与连接路由、只读授权、迁移锁、提交失败和重复调用；测试补齐六目标及非法目标零连接调用。复核通过。未运行本地单测。
- 提交/push：`main`，`feat: add isolated database migrations and role grants`；GitHub 验收结果在后续更新补录。
- 回退：未实际应用数据库迁移；本步代码/测试/SQL/文档可一起回退。已部署迁移不能通过 git revert 还原，需新增修复迁移或数据库备份恢复。
