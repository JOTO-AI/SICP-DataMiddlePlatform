## 工作流与报告

`.github/workflows/build-performance.yml` 推送时保留诊断运行。手动选择 `acceptance=true`、`profile=false` 时，BP01—BP06 与 BP08 冷/暖近似各 3 个独立 job，矩阵 `max-parallel=1`；每个 job 新建隔离数据库与卷。初始化准备完整运行但不冒充增量样本；准备时间和每轮端到端时间分别记录。BP02 严格每表 1 行，BP03 约 1%，BP04 增量 100% 替换，BP05 强制全量。

每次核心测量要求 `0 < T < 1800s`；目标摘要与独立生成器一致，生产可用探测在两份就绪和发布确认后记录终点。场景工件位于 `<BPxx>/<attempt>/stages.json`，公共工件包含 runner、进程与容器资源、日志、退出码。每轮额外采集 M/S 集群 WAL 差值（包含控制及采集写入，并非纯 COPY WAL）和四槽位新增读索引字节数。

`scripts/build_acceptance.py` 校验被测 SHA、profile 标记、退出码、固定规格、3 次完整样本、十四表规模/列宽/摘要/变化分布、真实计时边界及 M/S 独立 validate_copy 阶段。汇总全部样本的 min / median / max，不报告三样本 p95。任何缺失、失败或边界相等样本都拒绝通过。核心通过时仍输出 `full_acceptance_passed=false`，不能替代完整 B10。

Python 汇总器回归已加入常规 GitHub unit job；没有在本地执行。新增 Go/Playwright 测试分别由原 unit / integration / frontend job 执行。现有故障事务包装器补齐 COPY 转发，避免新导入路径使故障回归提前失败。

## BP07 在线负载入口

通过 `acceptance=false, profile=false, scenario=BP07` 独立运行。新增固定负载版本 `bp07-four-operations-v1`，是本次补充冻结的合成负载，不冒充此前已有实测基线。四个客户端各固定一种业务操作，最多四个请求并行，每客户端按 1 秒节拍发起请求；慢请求完成后才继续，不积压请求。请求使用夹具中的真实学生/教师身份，成绩第一页 10 条、课表为 2022-2023 第一学期，具体请求固定在 `onlineRequests`。

初始化后取得旧版本四接口响应摘要，运行 60 秒无更新基线，再在真实 1% 增量采集、构建、两份校验和发布可用期间持续运行同一负载。结束后取得新版本摘要，逐接口核对所有观测结果与对应组合版本一致；记录两阶段请求数、错误数、准确最近秩 p95、摘要计数、参考摘要与计时边界。每接口两阶段至少 30 个样本，拒绝未知版本、混读、任何 HTTP/业务失败、丢失样本、负载覆盖不完整、p95 恶化超过 20% 或 T >= 1800 秒。

内存限制包括每客户端最多 65536 个耗时样本、两个组合/每组合两个摘要；溢出失败，不抽样丢弃。客户端退出前等待当前请求结束并 join，25 秒请求超时及全局 deadline 提供上界。真实客户端的成绩分页快照保留正常 TTL，不调用 worker 专用释放方法，也不清空快照表来促使排空成功。

`TestI05_B10QueriesDuringBuild` 使用小夹具、短基线验证完整流程和一致性；工件明确 `LatencyGate=false`，不充当性能成绩。`TestI05_B10OnlineLoadRejectsMixedOrMissingEvidence` 覆盖混版本、缺失样本、接口失败与 20% 边界拒绝。上述测试未在本地执行。静态复核发现全容量教师课表每学期排课数可能超过现有前台扫描限额；BP07 会如实保留失败，不放宽前台预算，也不替换成空业务查询。

BP07 尚未进入核心三轮汇总，当前固定单一身份负载也不能代替所有业务分布；仍需对应 SHA 的 GitHub 样本、完整资源门槛及原版本对照。B10.02/B10.04 保持未完成。
