# I03：查询与读取协调集成

当前小步实现 I03-01、02、03、04、05、12，等待 GitHub 验收；I03-06—11 尚未实现，不勾选整组。

基线：每例独立六库、Redis 前缀和持久目录。通过真实 assembly/application/worker 完成十四类 HTTP Mock 输入的首次双份初始化，再由真实查询应用提供 HTTP 接口。网络 Mock 仅替换外部源和 SMTP，数据库、Redis、文件、控制事务、发布、缓存、查询和快照均走实际实现。

- 01：接口 4/5 按分数过滤后 total=1、G02 完整字段等于独立 grade_g02.json。
- 02：课程表保留不相关记录且缺少 C1；G01/G02 主记录保留，可空课程关系为空。
- 03：重命名真实成绩表注入 SQL 失败，接口必须明确失败，不能成功返回空列表；预先注册恢复。
- 04：冷/热缓存字段相同，用真实控制库 reader 数量证明命中未重新读取业务 SQL；错误 key 仍返回 401。
- 05：同一分页凭据逐页得到 G01/G02，无遗漏和重复，total 不变。
- 12：接口 6/7 完整排课数组对比独立 timetable_items.json；请求身份/学年/学期正确回显，不增加 total/分页字段。

输入取自 mock_data 的十四表快照并叠加 tests/fixtures/phase1/query/input.json 合成关系；预期文件依据 sicp-api-design.md 人工写定，未调用待测实现生成。未知字典码保留原码、名称为空，沿用 P06/P07 的确认规则。

复核：每例基线独立；Redis 适配边界只加唯一键前缀，Lua 和缓存实现仍执行真实 Redis 命令；清理只删本例前缀。GitHub 改为 I01→I02→I03 逐组执行，任一组失败立即停止后续组。Linux 静态编译通过；实际测试只在 GitHub 上执行。
