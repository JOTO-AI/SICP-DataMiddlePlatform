# B04 目标消费与完整复核

实现和静态 code review 完成，GitHub 验证待确认。

原生 TargetFiles 的数据库内容核对使用一次调用内的私有读取会话，绑定完整 manifest，缓存解析后的 chunk 清单。消费者仍检查每个 chunk 的字节数、SHA256、行数、每行字段类型、主键顺序、整表摘要和 EOF。会话不返回可持久复用的成功布尔值，不跨任务／副本／重试共享。关闭或父 context 取消后，已打开的会话迭代器也失效。

| 原读取 | 当前读取 | 覆盖窗口 |
| --- | --- | --- |
| SourceStorage 前置全量 Validate | 合并入必做数据库比较 | 读取前损坏、最后一行损坏、缺失／多行、摘要与类型错误 |
| 数据库逐行比较 | 保留，每份库独立执行 | 任意字段不一致，M 不能替 S 背书 |
| SourceStorage 结束 Validate | 保留完整复核 | 已消费 chunk 随后被替换／截断／删除，manifest 被替换 |
| Builder 开始／结束 Validate | 保留 | 表复用与构建期间文件变化，未凭相邻调用删除保护 |

仅内部 fileRows 可使用已完成 DecodeRecord 的对象；其他 CompleteSource 仍保留重新解码的防护。整表摘要仍使用原 Canonical 语义，缺键/null/数字字面值不变。单行消费由 Decode→Canonical→Decode 降为 Decode→Canonical。

BT04 新增读取计数回归：一行目标在数据库比较＋收尾复核中为两次文件核对、两次解码；增加已消费文件被篡改、跨组合和会话过期断言。既有文件损坏、EOF、排序、主键、取消和 M/S 不一致测试继续执行。没有新增后台 goroutine 或跨进程缓存。

本地仅 gofmt 与差异复核。扫描／解析计数断言、race 与容量分配收益待 GitHub 运行；不将理论次数减少写成实测时间。
