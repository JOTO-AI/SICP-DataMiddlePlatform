# I04：双份构建与发布集成

第一小步实现 01、02、03、09、10、11，等待 GitHub 验收，其余未实现，不勾选整组。

沿用每例独立六库、Redis 命名空间、文件目录和真实 application/worker 基线。HTTP Mock 新增半开区间 startTime/endTime 过滤并保留请求窗口审计，仍只读取 mock_data 与合成 query 夹具。

- 01：空控制状态不能查询；在第二份实际写入前暂停 worker，只有第一份 ready 时仍无路由、发布记录、成功进度及开放槽位。完成后确认十四表清单、两份真实 ready 证据、两个开放槽位及十四类进度。
- 02：十四类源分别注入 HTTP 500，使用十六个独立子用例中的十四个覆盖，每次失败均不创建候选、不发布、不推进进度；另两个子用例分别撤销 M0/S0 候选实际查询角色的 SELECT，校验失败同样不能发布。
- 03：真实 worker 发布期间持续读取 Redis，每个完整元数据必须等于持久 outbox 中某个完整目标；覆盖旧发布、同版本转移和新发布，禁止字段混合。
- 09：实际空增量窗口，保持组合和发布时间，不新增发布事件；十四类确认进度前进至本次 started_at，检查时间前进。
- 10：内容完全相同的强制全量仍创建两份新候选和新组合；读取 M1/S1 实际成绩表确认已写入，十四类摘要与旧内容相同。
- 11：全量、增量各自独立初始化后，从 Mock 删除 G01；全量只留 G02，增量保留 G01/G02，G02 完整字段继续匹配独立 expected。
