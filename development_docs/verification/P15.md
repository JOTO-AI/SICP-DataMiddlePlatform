## P15.02 持久受理

- Admit 以 execution 行锁串行检查幂等、已有执行/非终态/pending 及初始化状态，仅创建 accepted；提交成功才返回。相同请求先解析原任务再判断忙碌，适用于应答丢失后重试。
- 管理 HTTP 只接收幂等键和空正文，ID 由随机源生成，operator 取认证上下文；返回任务号/实际持久状态/受理时间，错误固定脱敏。首次强制全量明确提示初始化，不创建任务。
- StartAccepted 独立使用 worker 上下文，在冷却/pending/所有权检查后原子启动并修订调度；请求断连不会取消已受理任务。重复启动不重新计时。
- Review：检查受理与执行生命周期分离、同键跨操作者冲突、提交失败无成功响应、未知正文/null 拒绝、启动失败保留 accepted，以及并发最多一条新任务。仅 gofmt/diff，待当前 SHA CI。
- 回退入口后保留已受理任务/幂等键，由兼容 worker 继续或恢复；不删除已受理事实，不以 HTTP 返回码推断执行完成。
