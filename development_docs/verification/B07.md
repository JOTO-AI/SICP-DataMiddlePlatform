# B07 案例去重与固定版本复用

B07.01—B07.03 实现和静态 code review 完成，GitHub 验证待确认。新增分组路径针对代码中明确存在的逐教师重复整学期扫描；是否足以达到性能目标仍由容量工件决定。

成绩学生集合先扫描去重，再分别执行真实单学生和批量成绩入口；同一校验会话的两个操作共享该集合。学生课表按教学班＋课程缓存去重后的学年／学期，缓存满时回到源查询。教师按完整工号 token＋学年＋学期去重，保持首次出现顺序及原摘要顺序，不减少案例。

新候选、旧副本和无变化轮次均在固定读取资格内创建私有 QuerySession。小关联查询缓存绑定实例／槽位／代次／组合、表 scope／摘要、过滤条件、游标和批量大小；缓存空结果，深拷贝返回值。预算 32 MiB（含保守条目开销）及 10 万条目，单次结果超过 32 行不缓存，满后继续真实查询。会话关闭清除数据；不缓存跨重启就绪证据。

身份集合、学期映射有独立字节限制。B10 复核修正了容量必败边界：后台案例上限改为 100 万，学生/教师学期身份去重上限 32 MiB（其他集合上限不变）；固定夹具的约 3.46 万学生跨四学期不能被旧 10 万案例/8 MiB 上限截断。由于所有案例已在生成前按精确身份去重，移除再次序列化请求的重复去重表，保持首次出现顺序。新增流式 28 万关系→14 万独立案例回归。教师课表服务复用原 StaffMatches 校验逻辑逐行筛选，保留全部扫描与错误检查，但只保留匹配行，避免整学期收集后再筛选。前台 Scan 原有行数／字节／时间限制仍有效。

BT07 增加证据摘要与原直接调用路径差分、缓存空值／返回值隔离、换代拒绝、缓存满回源、取消后不可用。既有多教师、同号课程、跨学期歧义、缺失关联和晚出现非法字段回归继续执行。

教师课表新增同步 StaffGroup：最多 64 案例、待处理请求 1 MiB、保留行及分组引用 32 MiB。每组按学年/学期共享扫描及教师 token 解析，然后按原案例顺序使用与前台相同的 staffResponse、assembler、entries 和过滤逻辑。学生、成绩和全部学期案例仍完整执行，不以采样替代。教师组容量不足在任何响应输出前返回专用错误，调用方顺序重跑组内所有案例；其他错误不回退掩盖。

分组只在固定版本 QuerySession 的后台预算下开启，不跨会话保存结果，不新增 goroutine，不修改前台限额。保留原逐案例 Staff 路径作为参考；JSON 摘要仍使用原请求字节和原顺序。已发布前的四接口真实可用探测继续执行。预算还包括原会话缓存和每案例的保留载荷上限，32 MiB 不是进程 RSS 声明。

新增回归：70 教师跨分组的案例数/摘要与逐案例完全相同、同学期扫描次数下降；多学期、多教师、完整 token、空响应和末尾非法教师；容量耗尽与取消不输出部分组，MaxCases 不允许部分摘要。仅执行 gofmt 与差异复核，单元/race、SQL 扫描量及性能仍待 GitHub 验证。
