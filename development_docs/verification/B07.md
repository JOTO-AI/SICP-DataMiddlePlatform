# B07 案例去重与固定版本复用

B07.01／B07.02 实现和静态 code review 完成，GitHub 验证待确认。B07.03 的额外分组批处理路径仍待容量 profile 决定，暂不标记完成。

成绩学生集合先扫描去重，再分别执行真实单学生和批量成绩入口；同一校验会话的两个操作共享该集合。学生课表按教学班＋课程缓存去重后的学年／学期，缓存满时回到源查询。教师按完整工号 token＋学年＋学期去重，保持首次出现顺序及原摘要顺序，不减少案例。

新候选、旧副本和无变化轮次均在固定读取资格内创建私有 QuerySession。小关联查询缓存绑定实例／槽位／代次／组合、表 scope／摘要、过滤条件、游标和批量大小；缓存空结果，深拷贝返回值。预算 32 MiB（含保守条目开销）及 10 万条目，单次结果超过 32 行不缓存，满后继续真实查询。会话关闭清除数据；不缓存跨重启就绪证据。

身份集合、学期映射和案例序列化分别有字节限制。教师课表服务复用原 StaffMatches 校验逻辑逐行筛选，保留全部扫描与错误检查，但只保留匹配行，避免整学期收集后再筛选。前台 Scan 原有行数／字节／时间限制仍有效。

BT07 增加证据摘要与原直接调用路径差分、缓存空值／返回值隔离、换代拒绝、缓存满回源、取消后不可用。既有多教师、同号课程、跨学期歧义、缺失关联和晚出现非法字段回归继续执行。

本地仅格式和差异复核。SQL／扫描量、全部四接口差分和容量 profile 待 GitHub；若逐教师重复扫描仍是主因，需要继续实现 B07.03，不能据此宣称本阶段全部达标。
