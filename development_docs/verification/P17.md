## P17.03（2026-10-12）

批量关联：source.Filter 新增 Values 集合（最多 1000 项），使用绑定的 text[] 与 C 等值 ANY，不拼接用户值；空集合、混用单值/包含匹配、非法列和值在获取事务前拒绝。原单值与 strpos 字面包含逻辑不变。read.CollectKeys 去重并排序输入，每 1000 键共享同一 Handle 和 Budget 扫描，验证返回记录确实属于该组；LookupMany 要求关联键唯一，缺失保持缺失，冲突/后续 SQL 错误/预算失败均无部分结果。

内存与取消：新增 Budget.Reserve，将键、去重集合和关联索引按键字节加每项 64 字节的保守记账计入同一额度；源内容继续由 Scan/Retain 记账。每次读取继承剩余截止时间，跨多次关联不重置行数/批次/字节。该计数是受控预算，不声称等于实际 Go 堆内存；真实峰值由 I11 测量。

转换：Month/Date 仅接受冻结格式，校验真实日历和年份，空值 null、其他非法报错。Integer32 使用十进制字符串精确计算，不经过 float64，不分配巨大指数幂，覆盖带科学计数的整数、32 位上下界和非法小数；不猜测源学制正值限制。固定四条已知组织/学生类别映射，未知名称 null。

复核修复：Filter 加入 slice 后原课表测试不能再用 struct != 比较，改为 DeepEqual；补齐零数指数带首尾空白拒绝，避免提前返回零绕过字符串语法；追加第二次关联复用预算的回归。确认 read→compute 无循环依赖，源 SQL 标识来自固定目录，数组参数与调用方 slice 脱离。gofmt 与 diff --check 通过，无剩余阻断意见；测试执行按当前授权暂未核验。

容量估算（非实测）：35,000 键在每次关联每组 1000 键、每批 500 行且全部命中的情况下约 35×3=105 次 SQL（包括整批后的空批确认），而非逐身份 35,000 次。3.5 万基本+学籍+通讯合计至少 105,000 源行，超过默认 100,000；若再重复核对或关联开销则更高。实现人员服务时须减少不必要的全量附属读取，P24 冻结受控限额；当前不扩大默认预算，不宣称全量容量已验收。

索引核对：business_003 已为十四表主键提供 C 游标索引，并为排课提供班级课程/学期索引。人员按 XH/JGH/DWH/ZYH/XQH/BH 批量等值可复用现有索引；本步不新增重复索引。关系表按 JXBH+JHKCH 获取成员仍需 P21/P24 结合查询形态评估复合索引，以追加迁移交付，不修改旧迁移；所有实际 ANY 查询计划与容量在 I11 核验。
