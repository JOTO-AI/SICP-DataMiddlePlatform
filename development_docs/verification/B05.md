# B05 有界 COPY 与读取效率

实现和静态 code review 完成，GitHub 验证待确认。

worker 默认 `BUILD_IMPORT_MODE=copy`；显式 `insert` 保留原导入作为对照和回退。新窄接口 CopyExecutor 只接受一个有界且已绑定类型的批次，pgx 在现有事务内 COPY；表名和列顺序仍来自固定目录。逐批检查应答行数、提交，再累计成功行；失败不自动转 INSERT。

保留失效账本→TRUNCATE→分批导入→ANALYZE→完成账本的顺序，整个表继续持有原构建资格。部分提交或提交应答未知时不伪造续点；恢复由原完整表重建协议处理。没有取消唯一约束、fsync 或持久表。

每批最多 500 行（存储接口上限 1000）／8 MiB 原值载荷，超过批字节限制明确失败；不收集整表，不用 float 转换 JSON。COPY 与 INSERT 共用 value.Bind；JSON 仍写入 JSON，timestamp 仍保持无时区日历值。

后台读取批量提高至 1000，前台保持 500；复用单个 SQL 批内的扫描目标容器。保持 QueryDatabase 的 query 角色、固定槽位、完整逐列比较与 SQL 生命周期登记。

BT05 增加列顺序与绑定、错误行数、COPY／提交失败、适配器缺失不回退、二进制 JSON 字面值和 timestamp、配置测试。I01 增加真实 INSERT/COPY 数据逐字段差分、null／缺字段及重复主键拒绝。既有中断恢复、活动槽位和读者保护回归继续执行。

本地仅 gofmt 与差异复核。实际 CPU、内存、WAL、耗时对照待 GitHub 工件，不声明已达到单份 4 分钟。

复核依据：[当前 pgx JSON 编码实现](https://github.com/jackc/pgx/blob/v5.11.0/pgtype/json.go)、[COPY 实现](https://github.com/jackc/pgx/blob/v5.11.0/copy_from.go)。
