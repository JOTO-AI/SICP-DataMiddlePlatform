容量输入固定在 [operations_capacity_baseline.json](operations_capacity_baseline.json)：每源预置 10,000 条，白名单序列化事件 512—1,024 字节，每源每秒 100 条持续 60 秒，4 个历史客户端、8 个 SSE 客户端，30 天保留。运行器拒绝未经修改并审查该文件而降低目标。机器最低 4 个逻辑 CPU、8 GiB 内存；p95 ≤ 500 ms、RSS ≤ 512 MiB、积压 ≤ 1,000 个订阅事件、错误率 ≤ 1%、日志数据库总连接峰值 ≤ 64；同时要求实际成功写入达到计划速率的 90%。这些是待验证门槛，不是已测性能。

单实例故障会影响共享实例上的两逻辑库；按逻辑库禁止连接用于验证源隔离，不把它描述为两个独立 PostgreSQL 服务。通知用例使用合成地址及 Mock 通道；没有连接外部邮件或真实上游。测试的随机数据库名只用于隔离，合成事件 ID 携带运行 seed。

恢复执行时，先完成同 SHA 的 T27—T35 证据，再运行 `scripts/operations_acceptance.py`。运行器要求恰好 32 项且全部运行/通过，任何子项 skip/fail、超时、中断、非零退出、缺场景工件或缺容量实测数据均失败。超时/中断终止整个测试进程组并保留失败报告；外层隔离环境仍须按已有清理流程销毁。
