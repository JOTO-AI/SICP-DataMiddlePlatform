## P03.04：调用预算与共享冷却

- 实现：Coordinator 为每页固定 page/task/调用者最早截止时间，每次尝试再取 request 最早截止；排队、读取、退避和冷却都不重置页预算。TaskBudget 以互斥计数跨页/并发限制累计调用。Admission 在实际调用结束后释放，不以取消信号提前释放。
- 退避：上限指数退避和注入随机偏移，等待/随机失败明确停止；只有显式确认配置的 HTTP 临时状态可重试，令牌及未知业务码仍不可重试。具体阈值/状态以部署配置为准，没有实测生产值默认。
- 冷却：Retry-After 秒数/HTTP 日期转换后写固定控制 schedule.cooldown_until，原子 GREATEST 只能延长，不改调度时刻；每次请求前读取，冷却超剩余预算即失败，后续任务/重建组件不能绕过。保存使用独立五秒控制写预算，任务取消或超时后仍保留已收到的等待要求；控制读写失败则停止。
- review：复核最早截止、队列与退避计时、整数溢出、原子调用计数、保存失败、跨任务单例和取消后释放；补齐成功响应以及传输读取失败上的冷却要求。复核通过。
- 测试：T03-16/17 使用未来固定 FakeClock 与可控 transport，不依赖真实等待；并发 64 次竞争同一 16 次预算；控制仓储替身核对固定连接、只延长 SQL、提交失败和缺失单例。
- 集成边界：生产运行需单一上游共享 Coordinator/Admission，并沿用 P02 执行所有权；跨进程部署组装与恢复在后续阶段接入。本步不宣称集成完成。
