## P11.06 合并、限流与降级

- Coalescer 按完整 key 在单查询进程内合并，配置最大执行数/等待容量/独立执行期限；等待者和在途任务总数均有界。单等待者取消只结束自己；最后等待者离开可取消工作上下文，但任务/实际执行名额保留到回调真正退出，不给已废弃执行附加新等待者。Close 取消后等待真实工作结束，受自己的关闭期限约束。
- Work 必须在独立生命周期内取得并释放 SQL 读者资格，不能复用首个等待者的请求租约。P11.08 装配该规则。共享工作保留请求上下文值，但采用自身有界期限，不绑定首个等待者的取消。
- Executor 在任何缓存访问前确认固定句柄；缓存损坏/不可用有观测，在有界工作开始前再次核对位置，然后才允许合法固定槽位回源。热缓存不执行 SQL，回填仍使用首次组合生成的同一个 key。位置未决或关闭不能无条件降级。实际连接池上限在 P15 与同一配置预算对齐。

## P11.08 四接口完整查询管线

- Pipeline 注册四个实际处理器，按鉴权/严格解析→快照或活动组合→确认位置→结果缓存→独立固定读者→实际 SQL 登记/终止证明→释放→原 key 回填→读取当前组合同步元数据→完整响应执行。冷路径沿用已测的成绩/课表服务；热路径不登记 SQL 读者。
- Coordinator.AcquireFixed/read.ExecuteFixed 直接登记已选句柄，不再次解析活动路由。合并工作独立取得读者租约，等待者取消不提前释放；全部等待者离开仍由工作实际终止后释放。新活动组合不修改旧回填 key，同组合换位置复用结果键。
- X-Query-Snapshot 在鉴权和 JSON 解析后严格读取，只允许成绩接口，拒绝重复/空值/非法格式；仅成功响应输出，错误响应清除。快照冲突 409、容量超限 422、期限/取消 504；保留学生课表歧义 409。示例及 synced_at 规则加入公共契约。
- Review：逐层核对无缓存绕过鉴权、固定句柄/独立租约生命周期、先完整读取后成功响应、同组合复用与跨组合隔离、错误不回填、元数据每响应更新、输出快照头不能残留在错误响应。测试阻塞通道增加确定上限及失败清理；四接口实际 HTTP+Snapshot/Coalescer/Coordinator/read/业务服务运行，外部 I/O 使用线程安全替身。
