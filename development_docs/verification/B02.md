# B02 后台独立预算

实现及静态 code review 完成，GitHub 测试与容量验收待确认。

- 前台继续使用 `read.DefaultLimits`，保留 10 万行、64 MiB 累计扫描、20 秒约束。
- 完整存储检查按每表 manifest 行数核对，最多接受 1000 万行声明；到达行数后探测 EOF，多行、少行和末尾损坏均失败。候选、旧副本和无变化轮次共用 worker 的后台装配。
- 流式扫描限制每批载荷 16 MiB；后台业务计算 Collect 共用 64 MiB 保留载荷预算，不把累计扫描流量当作内存。案例仍有总数限制，不能通过截断获得成功。
- `BUILD_CHECK_TIMEOUT` 默认 30 分钟，范围 1 秒到 1 小时；每个内容／业务阶段受父 context 与自身期限约束。时间保护不表示端到端达标。没有异步放弃 SQL，原有读取资格释放协议保持有效。
- BT02 覆盖超过 10 万行、前台不放宽、额外／缺失行、过大声明、批与保留载荷超限、后台时钟和配置边界；现有游标、取消／SQL 结束、失败不 ready 回归继续执行。
- B01 容量入口不再接受旧预算耗尽作为预期通过结果。
