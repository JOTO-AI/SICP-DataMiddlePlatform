### 1.2 五个接口的需求

所有路径均为 `POST + JSON`，成功业务对象放入公共响应的 `data`。

| 接口 | 路径 | 主要行为 | 默认分页及排序 |
| --- | --- | --- | --- |
| 1 组织查询 | `/api/v1/sicp/organizations/query` | 根单位 `10001`、直属上下级、类别及有效状态筛选，默认包含停用组织 | `page=1`、`page_size=1000`；单位号升序 |
| 2 学生信息 | `/api/v1/sicp/students/query` | 基本、学籍、通讯、院系、校区、专业、行政班及辅导员信息；基本与学籍严格匹配 | `page=1`、`page_size=1000`；学号升序 |
| 3 教职工信息 | `/api/v1/sicp/staff/query` | 基本、通讯、所属单位；默认包含全部状态 | `page=1`、`page_size=1000`；工号升序 |
| 8 教师教学班 | `/api/v1/sicp/staff/teaching-classes/query` | 指定教师、学年、学期的教学班课程组合，完整教师列表及实际成员人数 | `page=1`、`page_size=100`；教学班号、计划课程号升序 |
| 9 教学班学生 | `/api/v1/sicp/teaching-classes/students/query` | 确认指定学期组合存在，按实际关系获取去重学生名单，缺档保留学号 | `page=1`、`page_size=100`；学号升序 |

接口 1—3 不传筛选条件表示查询全部对象，但仍分页。多个条件取交集，数组内取并集；过滤、去重及计数在分页前完成。接口 8 的 `total` 是教学班课程组合数，`student_count` 是该组合的成员人数；接口 9 的 `total` 是成员去重人数。

### 1.3 必须保持的公共约束

| 范围 | 实施要求 |
| --- | --- |
| 原值与身份 | 原单位号、学号、工号及课程/班级号保留前导零，不 trim、不整数化、不以姓名代替身份 |
| 关联与缺失 | 缺行、可空字段、格式错误、读取失败分别处理；可选关联缺失保留主对象及已有编号，SQL 失败不能转换为 null 或空列表 |
| 当前数据 | 学籍、通讯按既有入库归并规则保持每人最新整条记录；课程、人员归属均为当前组合内资料，不推断历史版本 |
| 存储边界 | 仍为十四张源业务表；业务转换在查询层进行；查询只读，不对源表补写单位、学生或关系 |
| 鉴权 | 每次请求先验证 `X-API-Key` 再进入缓存/快照/SQL；工具/MCP 限定终端用户查询范围，业务 key 不授予管理权限 |
| 读取一致性 | 一次请求的过滤、计数、分页、关联和时间元数据使用同一组合，不中途重新读取活动指针 |
| 失败行为 | 必须报错时整次请求失败，`data=null`；超预算不返回部分成功，失败结果不缓存 |
| 时间与日志 | `source_updated_at` 取实际参与记录最大 ETL_TIME，`synced_at` 取固定依赖集确认时间最小值；日志不记录完整人员响应、手机号、邮箱或凭据 |
| 执行方式 | 按小步串行开发、测试代码、复核和修复；测试沿用 GitHub Actions Linux 环境，本地只编辑、格式化及静态复核 |

学籍、学生通讯、教职工通讯的多记录规则已明确：现有字段没有可用业务更新时间，按解析后的 ETL_TIME 比较，整行选择最新；相同内容可归并，同优先时间内容冲突或时间不可比较则报错。查询层不能再次选择“第一条”掩盖存储问题，教职工基础、课程和单位等表也不能套用此例外。

**历史文档差异：** 总计划及早期字段规划包含“新增接口参与生产 query_validate”“学生缺学籍阻止新组合发布”的旧描述。按 2026-10-09 调整和当前实现，本计划采用存储/索引/发布身份校验作为生产构建门槛；学生严格匹配仍是接口 2 的查询契约及回归用例，不扩展成全部接口的生产发布阻断条件。验收时同时更新相关现行说明，保留历史记录的日期和语境。

## 2. 方案

### 2.1 开发与核对方式

延续第一阶段小步规则：`Pxx.yy` 对应一个完整行为及其正常/错误路径、测试代码和必要说明；实现后先 code review，修复问题后复核。后续获准实施时，按会话授权 commit/push，以对应 SHA 的完整 GitHub CI 成功作为下一小步门槛；本次写方案不自动执行提交、推送或部署。

P 复选框表示实现、测试代码及复核完成；T 仅表示对应测试已实际通过，两者分别记录。每阶段全部小步与 T 通过后进入依赖阶段；集成验收在全部 P/T 完成后执行。验证记录沿用 `development_docs/verification/Pxx.md`、`Txx.md`、`Ixx.md`，记录变更、决定、实际测试名、SHA、Actions 链接、通过/失败/跳过数和回退边界。现阶段不预建空“通过报告”。

**开发顺序：P16 契约 → P17 公共扩展 → P18 组织 → P19 教职工 → P20 学生 → P21 教学班共用能力 → P22 教师教学班 → P23 班级成员 → P24 正式装配与兼容 → P25 交付检查 → I07—I11。** 先完成依赖少的组织和教职工，再完成关联较多的学生；8、9 共用一套成员口径。全程不等待前端排期。

### 2.2 模块与读取设计

| 模块 | 复用/新增位置 | 职责 |
| --- | --- | --- |
| DTO、operation、解析 | `internal/query/contract`、`transport` | 新增五组完整 DTO；严格解析；按 operation 设置分页默认值 |
| 组织及人员 | 建议新增 `internal/query/organizations`、`people` | Organization/Department 组装、人员关联、字段转换、过滤、计数、分页 |
| 教学班与成员 | 建议新增 `internal/query/teaching`；复用 `timetable` 解析 | 同组合排课聚合、完整教师集合、跨学期判定、去重成员集 |
| 有界读取 | `internal/query/read`、`internal/storage/source` | 参数绑定、批量关联、同一 Handle、共享扫描/时间/内存预算 |
| 查询管线 | `handlers`、`cache`、`snapshot`、`metadata` | 扩展五种请求的缓存键、分页绑定、响应重组与依赖表目录 |
| 生产装配 | `internal/application/application.go`、`internal/service` | 注册真实服务和处理器；依赖缺失不得伪装可用 |
| 验证及迁移 | `internal/candidate`、存储迁移目录、`tests/integration` | 旧证据兼容、必要索引、Linux 真实库验证；业务预期留在测试夹具 |

初次实现不必搬迁现有成绩/课表代码。只抽取已经复用的教师拆分、学期解析和关系歧义检查，配套原四接口回归。教学班聚合不依赖课表条目的节次/日期组装：本接口只使用其需要的身份、学期和教师字段，不因无关排课展示字段缺失而无法统计班级。

读取原则：

1. 能在原字段上等值筛选的条件先通过参数化 SQL 收窄候选集合；名称包含复用区分大小写的字面子串语义，不将 `%`、`_` 当通配符。
2. 按源主键 C 排序分批读取，关联键批量加载；同一请求内可复用有界的目录索引，禁止每名学生/每个教学班逐项执行多次查询形成无界 N+1。
3. 业务转换后才能判断的筛选在查询层完成。计数覆盖完整候选集合；不得先 LIMIT 再过滤、只统计当前页，或将缺失关联行经 INNER JOIN 静默丢弃。
4. 默认复用 20 秒、100000 源记录、64 MiB 源内容、1000 批及 16 MiB 响应等现有请求预算；批量关联、聚合集合与重复读取均计费。人员全量关联可能超过现有扫描预算，P17/P24 使用基准规模评估并记录所需的受控配置，不能将默认预算当作已经足够，也不能直接套用后台构建预算。
5. 优先减少重复扫描和增加原表查询索引；若必须增加前台额度，保留有限上限并给出数据库连接、请求内存和耗时证据。索引采用新迁移，不重写已应用迁移，不增加持久派生业务表。

### 2.3 传输、缓存、快照与时间

**operation 建议值：** `organizations.query`、`students.query`、`staff.query`、`staff.teaching-classes.query`、`teaching-classes.students.query`。沿用现有点分标识，不能用共同路径尾段 `query` 作为缓存身份。

传输层复用 `X-API-Key`、四字段响应外壳、请求 ID、严格 JSON、错误码、超时和资源限制。五接口都支持快照分页：

- page 上限仍为 1000000、page_size 上限仍为 1000；接口 1—3 默认 1000，8—9 默认 100。默认值必须同时进入解析、SQL、缓存和快照绑定，不能只修改 DTO。
- 接口 8/9 学年学期必填，沿用相邻年份与 `1/2` 学期校验，不接受 `all`。接口 1 的 `is_active=false` 必须作为有效筛选，不能因布尔零值被当作未传。
- 首次响应返回 `X-Query-Snapshot`；后续分页回传，绑定 operation、组合、除 page 外全部有效条件及 page_size。默认有效期 5 分钟、可配置 1—60 分钟，不续期；过期或原组合已不可读返回 409，调用方丢弃本轮暂存结果重查。
- 原两个课表接口继续拒绝快照头，原两个成绩接口默认分页保持 100。新增接口的快照、缓存分派不得改变这四个接口的契约。
- 缓存键仍按组合、唯一 operation、规范化有效参数生成；可选 null/缺省等价，集合排序去重，保留精确字符串和 false，不包含 API key。只缓存业务内容，每次命中后重新组合确认的 `synced_at`。

**接口 8 → 9 的跨接口一致性：** 现有快照绑定 operation，不能把接口 8 的 token 直接用在接口 9。本期沿用已有响应头 `X-SICP-Combination`：调用方先完整分页取得接口 8 结果，再逐组合独立分页接口 9；每页核对组合号均等于接口 8 的组合号，并核对 `student_count == total == 累计唯一学号数`。发现版本变化、409、缺少组合头、读取失败或人数不符，整轮不应用，重新开始同步。重试应有上限及退避，持续变化时明确失败，不循环至无穷。

该方案提供“验证同版本后才能应用”，不承诺跨接口锁定旧组合或永不重试；五分钟 token 有效也不代表槽位必定保留五分钟。若调用方后续要求长时间锁定整个同步会话，另行约定跨接口快照协议，本期不偷偷放宽凭据绑定。

| 接口 | `synced_at` 固定依赖表（源表中文名） | `source_updated_at` 参与范围 |
| --- | --- | --- |
| 1 | 院系所单位 | 当前单位源记录 |
| 2 | 学生基本、学籍、学生通讯、院系所单位、校区、专业、行政班、教职工基础 | 实际返回学生及各关联源记录，含辅导员 |
| 3 | 教职工基础、教职工通讯、院系所单位 | 当前人员、当前通讯及所属单位 |
| 8 | 排课、课程、教职工基础、学生课表关系 | 该组合全部参与排课、课程、教师档案及计数关系记录 |
| 9 | 排课、学生课表关系、学生基本、学籍、院系所单位、行政班 | 用于组合存在判定的排课及该成员的关系、学生和归属记录 |

表名映射直接使用现有源目录，不通过请求传入。空结果也使用相同固定依赖集合；缺少任何已确认检查时间即报错。去重成员出现多条源关系时，人数只计一次，更新时间仍考虑全部参与关系记录。无变化轮次刷新同组合确认时间，不能让缓存保留旧 synced_at。

### 2.4 组织与人员的业务处理

**组织：** 以 `DWH` 唯一标识，返回全部 Organization 字段；`10001` 的父编号固定为 null。类别 code 保留原值，已知码映射名称，未知名称为 null。只有 `DWYXBSM="1" && SFSC="0"` 为有效，未知/空值为 false。父组织筛选仅匹配直属子级，默认不剔除停用组织；查询结果不自动补齐树节点。

**Department 共用对象：** 无单位号时为 null；有号但缺单位记录时返回 organization_code，其余字段均为 null，包括 is_active。关联到单位但状态码未知时 is_active=false。不能混淆“单位缺档”和“单位无效”，也不能据此过滤人员。

**教职工：** 从教职工基础表按 `JGH` 获取人员，关联通讯及单位。主工号、姓名必需，状态保留 DQZTM；按工号、姓名、单位号/名称、状态筛选。联系方式无记录/无值返回 null，已有值原样返回，格式异常或跨人员重复不清空。通讯表孤立记录不产生新教职工。有效状态 `11/23/04` 供调用方使用，不新增 is_active 响应字段或默认状态过滤。

**学生：** 以基本与学籍的严格匹配集合为核心，按以下字段组装；过滤使用同一来源，不能筛选一套值、返回另一套值。

| 响应/筛选字段组 | 来源与处理 |
| --- | --- |
| 学号、姓名 | 基本表 XH、XM，非空；姓名只作搜索 |
| status_code、enrollment_status_code、on_campus_flag | 学籍 XSDQZTM、XJZTM、SFZX，分别保留，不互相推导 |
| department、campus、major、grade、class | 学籍 YXSH、SSXQH、ZYH、SZNJ、SZBH；左关联单位、校区、专业、行政班；缺档保留已有编号、名称 null |
| student_category_code/name、study_years | 学籍 XSLBM、XZ；固定字典映射和整数校验，不能拿年级专业表的字段覆盖学籍 |
| admission_month、expected_graduation_date | 学籍 RXNY、YJBYRQ，按冻结格式转换；年份筛选取有效日期解析结果 |
| counselor | SZBH → 行政班 BH、FDYJGH → 教职工 JGH；无班级/无辅导员工号为 null，有号但无教职工保留工号、name=null |
| email、mobile | 学生通讯 DZXX、YDDH，最新整条记录原值返回 |

学生请求必须覆盖接口设计中的全部筛选：学号、姓名、院系号/名称、校区、专业、年级、行政班、当前状态数组、学籍状态数组、在校标识、学生类别数组、学制、入学年份、预计毕业年份和辅导员工号。缺少关联名称的记录不匹配名称条件，但无该条件时仍保留。学生有效状态 `01/05/08` 供调用方同步使用，不自动剔除其他状态。

### 2.5 教学班与成员的业务处理

共用四元标识 `(academic_year, semester, JXBH, JHKCH)`；行政班号不参与授课关系识别。

**共用成员组件：** 给定完整 JXBH/JHKCH，查询相关排课的所有有效学年学期，检查目标学期存在且组合没有无法区分的跨学期复用；只按目标学期读取会漏掉歧义，因此不能用于此检查。随后读取学生课表关系，按 XH 去重。缺失学号报错；无关系是正常 0 人，读取失败不是 0 人。跨学期歧义时即使成员为空也不能伪装为已确认的空名单。

**接口 8 查询顺序：**

1. 按指定学年、学期及可选 course_code 收窄排课，拆分 JSJGH 后按完整工号选择候选组合；工号不存在时返回正常空列表，不要求先匹配教职工档案。
2. 对候选组合收集该学期全部排课，合并完整教师集合。不能只聚合“命中查询教师的排课”，否则会遗漏同组合其他课次教师。
3. 以四元标识去重，按第 1.4 节处理名称冲突；课程按 JHKCH=KCH 关联，缺档保留计划课程号、课程名称 null，同号多课程报错。
4. 所有教师按工号去重并稳定排序，从教职工基础表获取姓名，缺档保留工号、name=null；不用 JSXM 的数组位置配对，也不因教师离职而移除关系。
5. 共用成员组件计算 student_count，不使用 XDRS；全体匹配组合验证后计数，按教学班号、计划课程号排序分页。任一匹配组合歧义/读取失败均使本次失败。

**接口 9 查询顺序：**

1. 先经共用组件确认目标组合存在及学期归属；组合不存在报错，组合存在但没有成员返回 `total=0, items=[]`。
2. 关系按学号去重，total 在关联人员信息前确定；按学号 C 顺序分页。
3. 仅为所需结果补充学生基本、最新学籍、院系、行政班；不复用接口 2 的严格匹配模式。学生缺基本信息或学籍仍返回学号，缺失字段为 null；无效状态也不移除。
4. 返回的院系、行政班明确为当前归属。全部分页在同一快照完成；调用方累计唯一学号数并核对 total 后才应用成员变更。

## 4. 发布与回退

1. 新接口代码、DTO、缓存/快照/元数据分派和生产装配必须一起交付，不能单独放开未接完整链路的路由。部署前核对旧组合存储证据可读、依赖表确认时间齐全。
2. 本次新增 operation 与旧四接口缓存自然隔离；旧四接口字段和语义保持既有约定。若共用代码变更实际改变旧接口语义，须补独立兼容及缓存失效方案，不能假定同组合旧缓存仍正确。
3. 需要索引时先完成新迁移与权限/预算验证，再部署对应二进制。源表字段和主键不变；无需为“新增查询接口”本身强制重新获取十四类上游数据。

5. 回退时下线五个新路由并恢复兼容二进制，调用方停止使用新接口及其 token；可保留新增只读查询索引。代码回退不会撤销已发生的数据发布、恢复被覆盖的槽位或延长快照有效期。
6. 前端后续可直接使用稳定契约开发接口中心与在线测试。本次接口验收不依赖页面上线，也不据此将整个第二阶段标记完成。
