# F12-04 前端容量与构建检查

2026-10-15，以下阈值在首次执行本项测量前登记。浏览器在当前 Windows 开发机使用 Chrome、单 worker；两个 origin 分别测量。HTTP 由既有后端捕获响应拦截；结果只能说明前端渲染/处理开销，不能代表真实网络、后端或 SMTP 延迟。使用 Vite 开发服务，生产包大小另外审计；服务器上线后还需生产环境基线。

| 检查 | 预先规定的上限 |
| --- | --- |
| 初次进入接口详情并可操作 | 10000 ms |
| 已捕获响应的查询至结果显示，每页 | 5000 ms |
| JSON 展开至有界文本显示 | 3000 ms；默认 4096 / 展开 65536 字符 |
| 1000 条 SSE 容量变体接收至待展示 | 5000 ms |
| 显示实时事件 | 3000 ms；历史 + 可见 + 等待合计最多 1000 条 |
| 场景峰值强制 GC 后 JS heap | 128 MiB |
| 退出后强制 GC 的 heap 相对初始增长 | 16 MiB；离页后 DOM < 2000 个元素，无实时列表/连接继续工作 |
| 生产 JS 总体积 / 单块 gzip | 1 MiB / 128 KiB |

正常查询与翻页逐字使用 `fixtures/v1/pagination.json` 的 students.query 第 1/2 页；大 JSON 使用已有响应增加 JSON 合法空白至 256 KiB，不制造业务字段。容量日志复制既有脱敏事件，仅将 event_id/sequence/cursor 改为独立容量协议编号；不是新增业务样本，不能作为真实日志吞吐验收。

测量与构建 JSON 报告写入 `artifacts/frontend-f12-04/`，登记环境、时间、输入来源、源码 SHA/工作区状态、构建文件 SHA-256；最终结果在执行记录追加。阈值失败先查原因，不能事后放宽阈值换取通过。
